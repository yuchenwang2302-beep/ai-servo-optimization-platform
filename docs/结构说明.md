# 代码结构

## Python 界面与运行层

| 文件 | 职责 |
|---|---|
| start_ui.bat / tools/start_ui.py | 固定使用项目解释器，在启动检查通过后打开登录界面 |
| tools/check_environment.py | 检查环境隔离、依赖版本及导入位置、MATLAB 安装和模型文件 |
| tools/setup_environment.ps1 | 按固定版本与哈希在新目录建立环境，不覆盖已有环境 |
| src/login.py | 使用布局管理的双语登录页、校园图裁剪与渐变、密码显示切换和登录事件；不能用旧 .ui 文件覆盖 |
| src/i18n.py | 统一英文项目名、中英文显示文案与占位符格式、当前语言、当前用户的语言偏好；不翻译内部算法键 |
| src/second_window.py | 装配两页，管理跨页运行锁和关闭行为 |
| src/responsive_page.py | 可滚动页面容器；宽屏左右排列，窄屏控制区在上、图表在下 |
| src/run_history.py | 识别运行记录、归档标记、保留策略、路径保护和过期数据清理 |
| src/history_dialog.py | 中英文记录列表、详情和清理设置；后台线程执行读取与清理 |
| src/identification_tab.py | 辨识页布局、初始图表及辨识结果展示 |
| src/optimization_tab.py | 优化页布局、模式选择、位置跟踪及优化结果展示 |
| src/algorithm_page.py | 共用表单、行内校验、运行状态/停止/进度、MAT 轮询、收敛图和统计标签 |
| src/notice_dialog.py | 参数错误、较大计算规模和关闭确认的非阻塞提示窗口 |
| src/algorithm_catalog.py | 算法入口、原始默认参数、临时数据文件名的唯一配置位置 |
| src/run_support.py | 输入校验、MAT 收敛数据读取和位置数据校验 |
| src/matlab_worker.py | GUI 侧监控线程：启动计算进程、状态通信、停止、时限、返回数据校验与进程清理 |
| src/compute_process.py | 独立计算进程入口：接收请求、执行 EngineTask、发送状态和保存结果 |
| src/engine_task.py | 仅在计算进程内执行 MATLAB 调用、模型依赖检查和 Engine 清理；保留原数值调用约定 |
| src/process_job.py | Windows Job Object：先挂起启动器、纳入私有进程组、再恢复；异常时仅清理本次进程树 |
| src/matlab_process.py | Windows 下仅针对本次持有句柄的进程完成退出清理 |
| src/project_paths.py | 从源码定位项目根目录和运行目录 |
| src/codes_rc.py | 由 assets/ui_resources.qrc 生成的 Qt 资源，不手工编辑 |

运行路径：固定启动入口 → 环境检查 → 登录 → 主窗口/算法页 → 校验参数 → 监控线程 → 独立计算进程 → MATLAB/Simulink → 本次 MAT 文件与最终返回值 → 图表/统计。监控线程不执行 MATLAB API；计算进程的标准输入/输出仅承载启动、停止及 JSON 状态消息，数值结果通过本次目录的 result.npz 返回并校验。监控线程完成资源清理后，Qt 自带的 finished 信号解除两页运行锁。

Windows 虚拟环境的 python.exe 会再启动基础解释器，因此必须在启动器运行前完成进程组归属，不能只在 Python 脚本内等待握手。私有 Job Object 禁止子进程脱离，并设置关闭句柄时清理成员；不按 MATLAB 进程名批量结束程序。具体时限及测试见 [验证说明](validation.md)。

各次运行的临时文件都放在 runtime，源码目录不应放计算结果。算法页只管理显示与运行状态，算法本身仍在 MATLAB 中。

所有算法通过 matlab_scripts/common/servo_save_progress.m 在每次完成迭代后发布完整 MAT 文件；先写临时文件再替换可读文件，界面约每秒读取一次。监控线程按单调时钟分别记录计算阶段与完整运行耗时，停止请求之后进入清理阶段。超时期间使用“正在停止”提示，完成进程回收后才报告最终状态。

清理线程只处理 runtime/identification 与 runtime/optimization 的直接子目录：要求标准运行名称、可读请求和状态元数据及结束状态。保留最近 30 天和最新 20 条未归档结束记录，归档保留整次运行；7 天后可单独清理结束运行的 Simulink 缓存。清理和归档共享跨进程文件锁，删除前检查绝对路径和全部后代的链接/联接属性。测试关闭自动维护以避免影响真实运行资料。

显示语言在登录界面选择，后台请求显式携带 `language`，计算进程在参数校验前应用它。单目标/多目标选择使用独立的 `single`/`multi` 数据标识；参数字典沿用现有键名。维护界面时，新增文案通过 `i18n.tr` 和集中翻译表呈现，不通过翻译后的显示文字判断算法分支。MathWorks/操作系统原始报错保留原文。

## MATLAB 模型配置

optimization/common/simulate_servo_position.m 共用三个评价函数的电机、逆变器、控制器初始化和仿真调用。单目标、多目标入口仍明确传入各自的模型名。

servo_search_bounds.m 保存原有两套边界：普通版本与 MDF 版本。MDF 的后四个上限仍为 300，最后一个下限仍为 10；没有统一数学定义。辨识函数具有各自的目标定义。

保留全部四个 .slx 模型。两个辨识模型的参考设置与输出有区别；两个优化模型也仍分别使用。文件名接近不能作为合并模型的依据。

辅助函数来源与原作者说明保留在 multi_objectives/support/，原始路径和校验值现纳入 docs/provenance/recovered_dependencies.json。

## 扩展位置

添加算法时，更新算法目录配置、MATLAB 入口和 EngineTask 调用约定，再验证输入约束与实际输出；不要在两个页面各复制一套运行代码。改变模型物理参数、搜索范围或评价指标属于实验定义调整，需单独记录并重新验证。
